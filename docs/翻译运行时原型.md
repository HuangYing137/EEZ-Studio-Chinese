# 翻译运行时原型与第一批中文资源

## 当前状态

本目录是在独立汉化仓库中建立的翻译运行时原型与首批术语资源。它**尚未接入官方 EEZ Studio 源码，也没有经过 EEZ Studio 构建验证**。因此当前不能称为已经生效的中文版。

## 文件

- `localization/runtime.ts`：无 Electron/React 依赖的纯 TypeScript 翻译函数原型。
- `localization/zh-CN.json`：同一批消息的 JSON 资源副本，便于后续改为资源文件加载。

## 接口设计

```ts
translate(
    id: string,
    fallback: string,
    params?: Record<string, string | number>,
    locale: string = "zh-CN"
): string
```

- 消息 ID 稳定，不随译文变化。
- fallback 保留英文原文，缺失译文时不会出现空白。
- 动态参数使用 `{{name}}` 格式；参数值由调用方传入。
- locale 不是简体中文时回退英文，避免未经翻译的语言误显示中文。
- 运行时不依赖 Electron，可供主进程和渲染进程共享同一实现。

## 第一批覆盖范围

当前原型登记了菜单、通用对话框按钮、文件过滤器、文件不存在错误和常见表单校验提示等消息。它们来自源码调查中已直接观察到的文字入口，是第一批试点，不代表全软件文案覆盖率。

## 下一步接入计划

1. 将本原型放入上游源码的共享模块目录，并验证 TypeScript 编译。
2. 让 Electron 主进程菜单通过统一消息 ID 取得标签。
3. 将通用对话框默认按钮和表单校验消息接入同一函数。
4. 确认主进程和渲染进程使用同一 locale 来源。
5. 在实际运行的软件中验证菜单、文件过滤器、错误提示、参数替换和英文回退。
6. 通过后再扩展到通知调用点、属性定义、控件组件、事件、仪器和帮助内容。

## 特别注意

不能仅凭此原型宣称完成汉化。官方源码目前的菜单、字段定义、通知调用点仍需逐处迁移；第三方组件及用户项目数据也需要明确边界。所有接入改动必须在独立分支中编译、运行和回归测试后再合并。
